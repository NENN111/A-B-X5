# Stage 2 — очистка и исследовательский анализ данных

## Статус данных

Исходные файлы X5 RetailHero пока не добавлены в `data/raw`. Поэтому Stage 2 реализует и тестирует pipeline, но не публикует схемы, распределения или выводы по эксперименту. Фактические отчёты появятся только после запуска на реальных файлах.

## Принципы

- Имена, типы, ключи и даты не предполагаются заранее.
- Все таблицы читаются через `Polars LazyFrame`.
- По умолчанию кардинальность оценивается приближённо, чтобы не создавать избыточную нагрузку на больших таблицах.
- Очистка преобразует `NaN` в `null` и удаляет только полные дубли строк.
- Пробелы, регистр, категории, даты и числовые выбросы автоматически не исправляются: для таких решений нужен смысл фактических полей.
- Raw-файлы остаются неизменными.
- Очищенные данные записываются атомарно в Parquet.

## Запуск

```bash
python -m src.data.preprocessing
```

Полезные параметры:

```bash
python -m src.data.preprocessing --keep-duplicates
python -m src.data.preprocessing --exact-cardinality
python -m src.data.preprocessing --raw-dir path/to/raw
```

## Артефакты

После успешного запуска создаются:

```text
data/interim/
  clean/
    clients.parquet
    products.parquet
    purchases.parquet
    uplift_train.parquet
  quality/
    cleaning_audit.json
    raw/
      dataset_overview.csv
      column_profile.csv
      numeric_summary.csv
      categorical_top_values.csv
      schema_inventory.json
    cleaned/
      ... те же отчёты после очистки
```

Артефакты исключены из Git и должны воспроизводиться из raw-файлов. `cleaning_audit.json` содержит число входных и выходных строк, удалённых строк и заменённых значений `NaN` для каждой сущности.

## Следующие решения после получения данных

После изучения фактических схем необходимо отдельно обосновать:

1. ключи и проверки уникальности сущностей;
2. допустимые значения treatment и target;
3. временной диапазон и дату начала эксперимента;
4. referential integrity между клиентами, товарами и покупками;
5. правила обработки невозможных цен, количества и скидок;
6. стратегию пропусков для конкретных полей;
7. признаки и срезы, допустимые без target leakage.

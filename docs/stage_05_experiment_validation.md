# Stage 5 — Experiment Validation

## Назначение

Stage 5 проверяет, можно ли доверять результату A/B-теста до перехода к uplift-моделированию. Слой состоит из четырёх независимых диагностик: SRM, A/A, bootstrap и анализа сегментов. Он не заменяет дизайн эксперимента и не превращает наблюдательные данные в рандомизированный эксперимент.

Фактические показатели не публикуются: в репозитории нет материализованной клиентской витрины из реальных X5 RetailHero данных.

## SRM

`src/experiments/srm.py` выполняет chi-square goodness-of-fit для размеров control и treatment. По умолчанию ожидается распределение 50/50, но доля treatment задаётся параметром `expected_treatment_share`.

Результат содержит наблюдаемые и ожидаемые размеры групп, chi-square statistic, p-value и флаг `srm_detected`. SRM проверяет механизм распределения трафика, а не различие бизнес-метрики. При обнаружении SRM интерпретацию uplift следует остановить до выяснения причины.

## A/A-симуляция

`src/experiments/aa_test.py` многократно случайно делит outcomes контрольной группы на две непересекающиеся части. Число успехов первой части генерируется из точного гипергеометрического распределения случайного разбиения, а второй части определяется остатком. Для каждой итерации сохраняются CR обеих частей, uplift, z-statistic, p-value и признак false positive.

Сводка включает долю false positives, среднее и медиану p-value, а также KS-диагностику относительно Uniform(0, 1). Для бинарной метрики p-value дискретны, поэтому KS p-value является диагностическим показателем, а не автоматическим критерием пригодности эксперимента. `random_state` обеспечивает воспроизводимость.

## Bootstrap uplift

`src/experiments/bootstrap.py` независимо ресэмплирует control и treatment с возвращением. Для бинарной метрики число успехов в bootstrap-выборке имеет точное биномиальное распределение с эмпирической CR; это позволяет не создавать матрицу индексов размером «iterations × clients». Сохраняются полное распределение absolute uplift, наблюдаемый эффект, mean/median и percentile confidence interval.

Bootstrap-интервал показывает sampling uncertainty, но не исправляет SRM, leakage или систематическую ошибку дизайна.

## Сегментный анализ

`src/experiments/segment_analysis.py` рассчитывает эффект по:

- возрастным группам;
- полу;
- RFM-сегменту;
- квантилю расходов;
- квантилю частоты покупок;
- группе давности покупки.

Для каждой строки сохраняются размеры групп, конверсии, CR, absolute/relative uplift, границы confidence interval, исходный и скорректированный p-value. Поправка Benjamini–Hochberg применяется единым семейством ко всем проверенным сегментам и контролирует False Discovery Rate. Основным признаком статистической значимости для исследования сегментов является `significant_adjusted`, а не `significant_raw`.

Возрастные интервалы: `до 25`, `25–34`, `35–44`, `45–54`, `55–64`, `65+`. Recency-группы строятся из `recency_score`: 1 — давние, 2–3 — средняя давность, 4–5 — недавние. Строки без обеих экспериментальных групп не тестируются, потому что uplift для них неидентифицируем.

## Запуск и артефакты

После Stage 3 выполните:

```bash
python -m src.experiments.validation
```

Параметры воспроизводимости и объёма вычислений:

```bash
python -m src.experiments.validation \
  --expected-treatment-share 0.5 \
  --alpha 0.05 \
  --aa-simulations 1000 \
  --bootstrap-iterations 10000 \
  --random-state 42
```

По умолчанию результаты записываются в `data/processed/experiment_validation/`:

- `srm.parquet`;
- `aa_summary.parquet` и `aa_simulations.parquet`;
- `bootstrap_summary.parquet` и `bootstrap_distribution.parquet`;
- `segment_analysis.parquet`.

Запись каждого файла атомарна. Эти таблицы подготовлены для notebook, PostgreSQL-витрин и Power BI.

## Стратегия тестирования и польза

- SRM сравнивается с эталоном SciPy и проверяется на сбалансированном, несбалансированном и плановом 75/25 распределении. Это защищает ожидаемые counts и решение по alpha.
- A/A проверяется на воспроизводимость, отсутствие false positives при константном outcome и разумную частоту ошибок первого рода на фиксированной выборке. Фиксированные seed и широкая статистически обоснованная граница устраняют flaky-тесты.
- Bootstrap проверяется на воспроизводимость, известный observed uplift и вырожденные выборки с нулевой шириной интервала. Это ловит перепутанный знак и неверное ресэмплирование групп.
- Benjamini–Hochberg сравнивается со Statsmodels. Сегментные CR и uplift проверяются вручную, чтобы защитить направление эффекта и контракт таблицы.
- Интеграционный тест проходит весь путь Polars LazyFrame → диагностики → шесть Parquet-файлов. Он обнаруживает несовместимость между отдельными модулями.
- Полный регресс, Ruff и проверка notebook подтверждают совместимость с предыдущими stages.

## Ограничения

- A/A на одной контрольной группе диагностирует реализацию теста и поведение метрики, но не доказывает корректность исходной рандомизации.
- Percentile bootstrap не является studentized или BCa interval.
- Сегментный анализ исследовательский: различие «значимо в одном сегменте, незначимо в другом» само по себе не доказывает различие эффектов между сегментами. Для подтверждения нужен тест взаимодействия.
- Малые сегменты дают нестабильные оценки; размеры групп всегда сохраняются рядом с эффектом.
